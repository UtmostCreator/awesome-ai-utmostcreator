## Context

This is a PHP-first AI workflow kit installed INTO other repositories. A completed Tier
A/B/C review of external tooling has already classified every candidate tool. Tier A
tools are recommended for direct, optional-first integration into this kit. Tier B tools
are recommended in documentation only, for consumer repos, and must never be bundled.
Tier C tools are fully discarded (name-only mention, no action). This plan turns that
completed review into ONE bounded, evidence-grounded implementation plan.

## Plan Corrections (Fact-Check Applied, 20260705)

An independent repository-researcher fact-check of this plan's claims found three
corrections, applied throughout this document:

1. **`scripts/run-link-check.sh` does NOT exist** (confirmed: file not found on disk).
   `justfile:223`'s `lint` recipe calls `@bash scripts/run-link-check.sh`, meaning
   `just lint` currently references a **missing script** and fails at that step. This
   is a **pre-existing bug**, unrelated to this ticket's scope — it must be flagged in
   the new doc, NOT silently treated as working, and must NOT be fixed as part of this
   slice (fixing it is a separate follow-up). lychee is wired only inline in
   `scripts/ai/ai-doc-check.sh:122-125` (this part of the original claim was correct).
2. **markdownlint naming mismatch:** `scripts/ai/ai-doc-check.sh:111-112` invokes the
   plain `markdownlint` binary (`if command -v markdownlint >/dev/null 2>&1; then ...`),
   not `markdownlint-cli2`. `.markdownlint-cli2.yaml` exists at repo root and implies
   the cli2 variant is expected, but the script calls the generic binary name. The new
   doc must describe this precisely (tool invoked: `markdownlint`; config file name:
   `.markdownlint-cli2.yaml`) rather than asserting "markdownlint-cli2 is wired."
3. **Infection coverage risk was overstated in the original review; the real gap is
   different.** `tools/ai/install/**` has substantial behavioral PHPUnit coverage: 38
   test files exercise at least 17 distinct install source files with real function
   calls and assertions (for example `InstallerSafetyTest` has 68 test methods,
   `StackDetectionTest` calls `aiStackDetect()`/`aiStackLoadRegistry()` against temp
   roots). The "misleadingly low MSI due to thin/absent coverage" risk is **not
   grounded** for this surface. The actual gap: **`phpunit.xml.dist` has no
   `<source>`/`<coverage>` block.** PHPUnit 11 requires an explicit `<source><include>`
   allowlist for coverage collection, and Infection depends on that coverage data to
   scope mutants efficiently. Without it, Infection will either fail to collect
   coverage or fall back to a full-suite-per-mutant run (slow, not silently broken).
   Phase 2 must add a scoped coverage block and verify a coverage driver (Xdebug or
   PCOV) is enabled before the smoke test can succeed within budget — see the new
   Phase 2 Todo item and AC-13 below.

## Problem

A Tier A/B/C tool review has already been completed for this kit but has not been
persisted or actioned:

1. Tier A tools (Infection mutation testing; markdownlint and lychee, both already
   wired into scripts but not formally documented as recommended-optional; actionlint/
   shellcheck/shfmt already wired and needing no action) have no formal recommendation
   doc and, in Infection's case, no integration at all.
2. Tier B tools (OSV-Scanner, jscpd, Trivy, Renovate, Serena/Aider) have no doc-only
   recommendation surface for consumer repos.
3. Tier C tools are fully discarded but have no single reference point recording that
   decision, risking re-litigation of already-closed evaluations.
4. Several open decision points from the review (composer.json placement, guard
   pattern, doc placement, test/config placement, AI-eval overlap-audit scope, approval
   boundary, risk/rollback posture) must be resolved precisely enough to hand directly
   to an implementer with no further clarification.

## Contracts And Boundaries

- Composer dependency-surface contract: `require` stays PHP-only forever; new optional
  dev tooling enters only via `suggest` (this slice) or `require-dev` (existing
  precedent for Laravel Prompts) — never `require`. `composer validate` must pass after
  the `suggest` block is added.
- Justfile default-gate contract: `test:` and `ci:` recipes are a closed, reviewed set;
  new heavy/optional recipes must be additive siblings, never folded into those two
  without a separate, explicit approval (this itself is the enforcement of the
  v0.6-plan's "never a default gate" pre-decision).
- Generated-vs-hand-maintained doc contract (`docs/ai/generated-artifacts.md`,
  `docs/ai/repo-required-tools.md:3`): tool documentation for tools not referenced
  inside `scripts/ai/*.sh` belongs in a new hand-maintained doc, never as a hand-edit of
  a generated file.
- Execution-protocol budget contract: every new heavy command class must get a stated
  timeout budget before it is safe to invoke unattended (this slice adds the missing
  mutation-testing entry).
- Approval-boundary contract: `docs/ai/architecture-locks.md` and
  `docs/ai/approval-boundaries.md` both require asking before dependency-surface
  changes; Phase 2 (composer.json + justfile + infection.json5) is gated on that
  approval. Phase 1 (pure documentation, no dependency surface, no code) is not.
- Guard-pattern contract: the new `mutation-test` recipe uses a `vendor/bin/infection`
  existence check (`[[ -x vendor/bin/infection ]]`), not a `command -v` PATH check,
  because Infection ships as a Composer vendor-bin tool, not a system CLI — the guard
  *shape* still mirrors `scripts/ai/ai-doc-check.sh`'s detect → run-or-explain pattern
  (never a hard crash with no guidance).

## Risks And Rollback

- RISK (dependency-surface approval): Phase 2 touches `composer.json`'s dependency
  surface (new `suggest` block) and adds a new always-invokable `justfile` recipe.
  Per `docs/ai/architecture-locks.md` ("ask before changing ... dependency surface")
  and `docs/ai/approval-boundaries.md` ("dependency installation ... ask before"),
  explicit human approval is REQUIRED before starting Phase 2. Present the
  `suggest`-vs-`require-dev` open decision point to the maintainer at that time.
- RISK (wrong composer placement): Adding Infection into `require` or even
  `require-dev` (rather than `suggest`) would grow every contributor's default
  `composer install` footprint for a heavy, whole-suite-per-mutant tool, contradicting
  the already-approved v0.6-plan Phase 8.2 note that mutation testing must be
  "approval-gated; never a default gate." Mitigation: `suggest`-only + AC-04 lock this.
- RISK (unverified cache directory name): The exact name of Infection's local cache
  directory for the currently-adopted Infection version is unknown (assumed
  `.infection/` based on common defaults). Mitigation: implementer must verify against
  the actual installed version before finalizing the `.gitignore` entry (AC-07).
- RISK (open decision point — require-dev parity): The maintainer may prefer
  `require-dev` parity with the Laravel Prompts precedent over the stricter
  `suggest`-only recommendation in this plan. This is flagged as an open decision
  point, not blocking, since `suggest`-only is safe-by-default and easy to upgrade to
  `require-dev` later if desired.
- RISK (coverage prerequisite, fact-check finding): `phpunit.xml.dist` has no
  `<source>`/`<coverage>` block today; PHPUnit 11 requires one to collect coverage,
  and Infection needs that coverage to scope mutants efficiently. A repository-level
  fact-check found `tools/ai/install/**` already has substantial behavioral test
  coverage (38 test files exercising ≥17 source files), so a misleadingly-low-MSI
  risk from thin tests is NOT expected — the real risk is Infection failing to run
  at all if no coverage driver (Xdebug/PCOV) is enabled, or running slowly via a
  full-suite fallback if the `<source>` block is missing/misconfigured. Mitigation:
  AC-13 requires the scoped `<source><include>` block, and the Verification Plan
  requires confirming a coverage driver is present before the smoke test.
- RISK (pre-existing broken `just lint` step, fact-check finding): `justfile:223`
  calls `scripts/run-link-check.sh`, which does not exist on disk — `just lint`
  currently fails at that step independent of this plan. This must be documented in
  the new doc as a known, pre-existing issue (not introduced by this slice) and must
  NOT be fixed here; file it as a separate follow-up ticket. DISABLE LEVER (for the
  Infection concern specifically): simply stop invoking `just mutation-test` — it is
  wired into no default gate, so no other command or CI surface is affected.
- ROLLBACK: The change is additive (one new doc + one new config file + one new
  justfile recipe + one new composer `suggest` entry + one new `.gitignore` line + one
  new execution-protocol budget entry). Revert: delete `infection.json5`, drop the
  `mutation-test` justfile recipe, drop the `suggest` composer entry, revert the
  `.gitignore` line, and revert the execution-protocol budget entry to restore prior
  behavior. No data migration, no engine change, so rollback is a straight `git revert`
  of the touched files — matching the additive-only rollback posture of the Laravel
  Prompts precedent.
