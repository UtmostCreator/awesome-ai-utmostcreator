# Design Principles

This root file is the short guide version.

See `docs/foundations/DESIGN-PRINCIPLES.md` for the maintained canonical copy.

## Base Principles

- keep one neutral workflow model
- keep always-on policy short
- keep reusable procedure in capability folders
- keep the default choice model small and obvious
- prefer the core four agents for code development
- add `release-auditor` and `refactorer` only when they clearly fit
- document fallbacks for surface-limited features
- prefer evidence over confidence language
